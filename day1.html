단계 2 · Imager 에서 고르고 쓰기 (20분)

📍 지금 어디 · 왜

카드 쓰기는 기다리는 시간이 깁니다. 값을 한 번에 다 넣어 두면 첫 부팅 뒤 다시 설정할 일이 없습니다.

Raspberry Pi Imager — 고르고 적는 값
① 장치Raspberry Pi 5
② 운영체제Raspberry Pi OS (64-bit) — 데스크톱판
③ 저장소microSD 카드 (용량으로 확인 · PC 디스크를 고르지 않는다)
④ 호스트 이름자리 번호로 — pi-01 · pi-02 …
④ 위치Seoul → 시간대 Asia/Seoul · 무선 국가 KR
④ 사용자사용자 이름 · 비밀번호 (강사가 칠판에 적은 것)
④ 무선 LAN교육장 무선 이름(SSID) · 비밀번호
④ 원격 접속SSH 켜기 — 비밀번호 인증
④ Raspberry Pi Connect끈다 (이번 수업에서 쓰지 않음)

단계 4 · PC에서 접속 — 한 방향만 됩니다 (5분)

📍 지금 어디 · 왜

교육장 PC는 유선, 보드는 무선입니다. PC에서 보드로는 닿지만 보드에서 PC로는 닿지 않습니다(2026-11-22 확인). 그래서 이후 모든 파일은 PC 쪽에서 움직입니다.

💻 PC 에서 작업PowerShell · 보드가 아니라 내 PC

PC의 PowerShell 에서 (IP 는 단계 3 에서 적은 값):

💻 PC · PowerShell

처음 접속하면 yes 를 한 번 묻고, 그다음 비밀번호를 묻습니다(쳐도 화면에 안 보이는 것이 정상).

👀 볼 것 — 프롬프트가 사용자이름@pi-__:~ $ 로 바뀌면 보드 안입니다. 이제 모니터는 빼도 됩니다.

🆘 안 되면 — 개인 노트북을 유선에 꽂은 분은 다른 대역이라 ping 이 안 될 수 있습니다 → 교육장 PC를 씁니다.

선택 · VNC — 보드 화면을 PC 에서 보기 (5분)

📍 지금 어디 · 왜

실습 1~6 은 ssh 창만으로 됩니다 — 이 단계는 건너뛰어도 됩니다. 모니터를 치운 뒤에도 보드의 데스크톱 화면(브라우저 · 설정 창)을 PC 에서 보고 싶을 때만 켭니다. VNC 는 화면을 통째로 보내므로 ssh 보다 느립니다.

보드에서 (ssh 창) — VNC 를 켭니다:

🍓 보드 · ssh 창
sudo raspi-config

파란 메뉴에서 Interface Options → VNC → Yes → Finish (화살표 키 · Enter). 켜졌는지 확인합니다:

🍓 보드 · ssh 창
ss -ltn | grep 5900

👀 볼 것 — LISTEN 이 들어간 줄이 나오면 VNC 가 5900 번 포트에서 기다리는 중입니다. 아무것도 안 나오면 위 메뉴를 다시 봅니다.

💻 PC 에서 작업PowerShell · 보드가 아니라 내 PC

PC 에서 보드의 5900 번에 닿는지 보고, VNC 뷰어가 없으면 설치합니다:

💻 PC · PowerShell
Test-NetConnection 10.10.220.___ -Port 5900
winget install --id RealVNC.VNCViewer -e

RealVNC Viewer 를 열고 위쪽 주소 칸에 보드 IP(10.10.220.___)를 넣고 Enter → 처음 한 번 묻는 보안 확인에 Continue → 보드의 사용자 이름 · 비밀번호(단계 1 에서 정한 것)를 넣습니다.

👀 볼 것 — Test-NetConnection 끝줄 TcpTestSucceeded : True, 그리고 뷰어 창에 보드 데스크톱이 뜨면 됩니다. 한글이 □ 로 보이면 단계 5 의 fonts-nanum 을 설치했는지 봅니다.

🆘 안 되면 — TcpTestSucceeded : False → VNC 가 꺼져 있거나(보드에서 ss -ltn | grep 5900) 같은 망이 아닙니다(단계 4 의 ping) · 뷰어가 「보안 방식이 맞지 않는다」고 하면 → 보드의 VNC 서버(WayVNC)와 맞지 않는 뷰어입니다. RealVNC Viewer 를 씁니다 · winget 이 막혀 있거나 설치 권한이 없으면 → 강사에게(교육장 PC 설치 권한).

[사실] 2026-11-27 강사 노트북(RealVNC Viewer 7.12.1)에서 보드 pi-01 의 5900 번 연결 확인 · 보드 VNC 서버는 WayVNC. [확인필요] 교육장 PC 에 VNC 뷰어가 있는지 · 설치할 수 있는지.

이틀 동안 실습 여섯 개를 합니다. 따로 떨어진 여섯 개가 아니라 보드 한 대 위에서 같은 모델을 따라가며 한 바퀴를 도는 여섯 단계입니다.

1일차에는 이 기계가 무엇인지 읽고(메모리 예산), 한 장을 찍어 맞히는 데 걸리는 시간을 제대로 재고(기준선), 모델을 줄여서 다시 잽니다. 2일차에는 모델 앞의 센서와 전처리를 줄이고, 한 번이 아니라 계속 돌리며 추론 주기와 대기 전력을 재고, 마지막에는 일부러 망가뜨려 오류가 안 나는 고장을 갈라냅니다. 어느 장을 읽든 지금 고리의 어디쯤인지 떠올리면서 읽으시면 흐름을 놓치지 않습니다.

측정하지 않은 것은 모르는 것입니다

소프트웨어 테스트는 “동작하는가”를, MLOps 는 “두 번 돌려 같은가”(재현성)를 판정합니다. 온디바이스 AI는 판정할 대상이 다릅니다. 보드마다, 케이스마다, 심지어 같은 보드도 켜고 5분 뒤와 30분 뒤의 숫자가 다르기 때문에 정답 수치를 미리 정해 둘 수가 없습니다. 그래서 이 과정의 점검 도구는 숫자가 몇이냐가 아니라 제대로 재었느냐를 봅니다. 첫 추론을 따로 두었는가, 여러 번 재었는가, p95를 봤는가, 대기 전력을 쟀는가, 조건을 적었는가.

훈련생에게도 같은 순서로 가르치십시오. 인터넷에 떠도는 “몇 배 빨라졌다”가 왜 내 보드에서 안 맞는지는 설명으로 납득시키기 어렵습니다. 이틀이면 몸으로 압니다. 직접 재 보면 되기 때문입니다.

반대로 장치 안에서 돌린다고 더 정확한 모델을 쓸 수 있는 것은 아닙니다. 장치는 서버보다 작습니다. 정확도를 얻으려고 장치로 가는 경우는 없고, 지연·프라이버시·오프라인·비용 가운데 무엇을 얻으려고 정확도의 일부를 내주는 쪽입니다. 평가 문항에도 이 구분이 나옵니다.

교재 1부 2-2모델 탑재 판정 — 실행 중 메모리 기준

실습 1에서는 모델 후보 여섯 가지를 놓고 이 보드에 올라가는지 판정합니다. 판정 기준은 파일 크기가 아니라 실행 중에 쓰는 메모리(런타임 메모리)입니다. 파일을 여는 순간 런타임이 칸을 잡고, 중간 계산 결과를 담을 자리를 잡기 때문에 실행 중 메모리는 파일보다 큽니다.

판정은 세 줄로 합니다.

  1. 쓸 수 있는 메모리를 읽는다. 전체가 아니라 지금 비어 있는 양입니다(MemAvailable).
  2. 거기에 안전 여유를 곱해 이번에 쓸 수 있는 예산을 정한다. 나머지는 운영체제·카메라·우리 코드 몫입니다.
  3. 후보의 실행 중 메모리가 예산보다 크면 no-fit(불가). 판정 옆에 숫자로 된 근거를 함께 적는다.

예를 들어 쓸 수 있는 메모리가 3,500MB이고 안전 여유를 60%로 잡으면 예산은 2,100MB입니다. 실행 중 2,400MB가 필요한 모델은 3,500MB보다는 작지만 예산을 넘으므로 불가입니다. “꽉 채우면 죽습니다”가 이 계산의 이유입니다.

TFLite LiteRT
이름 옛 이름 새 이름 (Lite Runtime)
파일 확장자 .tflite 그대로 .tflite
파일을 바꿀 필요 — 없다
개발 — 새 이름 쪽에서 계속된다

구글은 2024년 9월 4일 “LiteRT는 TensorFlow Lite의 새 이름”이라고 발표했고, .tflite 파일 확장자와 포맷은 바꾸지 않는다고 밝혔습니다. 앞으로의 개발은 새 이름의 런타임에서 이어지며, 텐서플로뿐 아니라 파이토치·JAX·Keras로 만든 모델도 다룬다고 설명합니다 [R-2]. 파이썬에서는 ai-edge-litert 패키지가 새 이름의 런타임입니다.

이 과정의 기본 런타임도 LiteRT입니다. 2026-11-08에 확인해 보니 ai-edge-litert 2.3.0은 라즈베리파이 같은 Arm 64비트 리눅스용으로 파이썬 3.11·3.12·3.13 설치 파일이 모두 있었고, 옛 이름의 가벼운 판(tflite-runtime)은 Arm 64비트용 파이썬 3.11 설치 파일을 찾지 못했습니다 [실측·PC]. 이름만 바뀐 것이 아니라, 새 보드에 설치되는 쪽이 새 이름입니다.

모델을 처음 한 번 돌리는 시간은 그 뒤와 다릅니다. 런타임이 메모리를 잡고, 연산을 준비하고, 캐시가 데워지느라 느립니다. 그 값을 평균에 섞으면 평균이 거짓말을 합니다. 그렇다고 버리면 안 됩니다. 켜자마자 답해야 하는 장치라면 첫 추론이 더 중요하기 때문입니다.

무엇 무엇을 말하나 어디에 쓰나
첫 추론 켜고 처음 답하기까지 켜자마자 답해야 하는 장치
평균 보통 얼마나 걸리나 초당 몇 번 돌릴 수 있나
p95 스무 번에 한 번은 이보다 늦다 가끔 늦는 것이 문제인 장치
최대 최악 시간 제한이 있는 장치
조건 보드, 런타임, 입력 크기, 온도 같은 조건에서 잰 값끼리만 견준다

평균만 보면 가끔 느린 순간을 놓칩니다. 예를 들어 평균이 48ms인데 p95가 205ms라면, 평균만 보고 “초당 20번은 돌린다”고 말하면 안 됩니다. 스무 번에 한 번은 200ms를 넘기 때문입니다. 평가 Q6이 이 형식입니다. 분류 모델 평가에서 “정확도만 보면 놓친다”는 이야기와 같은 구조라고 이으셔도 됩니다.

프루닝은 2015년 한(Han) 등이 “중요한 연결을 먼저 배우고, 중요하지 않은 연결을 잘라 낸 뒤, 남은 것을 다시 학습한다”는 세 단계로 정리했습니다. 같은 정확도에서 AlexNet의 파라미터를 9배, VGG-16을 13배 줄였다고 보고했습니다 [R-10]. 다만 이것은 파라미터 수가 줄었다는 이야기입니다. 규칙 없이 흩어진 0을 건너뛰어 주는 연산 라이브러리나 하드웨어가 없으면, 빈칸이 많은 행렬도 꽉 찬 행렬과 똑같이 계산됩니다 [의견].

증류는 2015년 힌턴(Hinton) 등이 “여러 모델의 앙상블이 가진 지식을 배포하기 훨씬 쉬운 단일 모델로 압축한다”는 방법으로 제안했습니다 [R-11]. 큰 모델의 답(확률 분포)을 작은 모델이 따라 배웁니다. 큰 모델을 먼저 만들어야 하므로 줄이는 데 드는 비용이 오히려 큽니다.

LiteRT 문서는 학습이 끝난 뒤 하는 양자화(post-training quantization)를 이렇게 나눕니다. 동적 범위 양자화는 데이터 없이 최대 75%까지 줄고 정확도 손실이 가장 작으며, 정수 양자화는 이름표 없는 대표 표본이 필요하고 최대 75%까지 줄며 정확도 손실이 조금 있고, 정수 전용 가속기(Edge TPU 등)에서도 돌아갑니다 [R-7]. 정수만으로 추론하는 방식과, 양자화 뒤에도 정확도를 지키도록 학습을 함께 설계하는 방법은 2018년 제이콥(Jacob) 등의 논문이 정리했습니다 [R-8]. 학습 중에 양자화를 흉내 내는 쪽(QAT)은 정확도를 더 지키지만 다시 학습해야 해서, 12시간 과정에서는 학습 뒤 양자화(PTQ)만 합니다.

대표 데이터셋(representative dataset)은 “값이 대체로 어디까지 가는지 보여 주는 표본”입니다. 실수를 정수 256칸에 밀어 넣으려면 어디부터 어디까지를 256칸으로 나눌지 정해야 하는데, 그 범위를 대표 데이터셋을 흘려 보며 정합니다. 대표 데이터셋이 실제와 다르면 범위가 엇나가고, 정확도가 오류 없이 조용히 떨어집니다. 이 개념이 2일차 오후 고장 진단(값 범위 고장)의 뿌리가 됩니다. → 제2부 4-2

교재 2부 4-2양자화 계산 예제 — scale 과 zero point

실수 weight 다섯 개를 8비트 정수(-128~127)로 바꿔 보겠습니다. 최솟값과 최댓값 사이를 256칸으로 나누고(scale), 실수 0.0이 놓일 정수 자리(zero_point)를 정합니다.

import numpy as np
w = np.array([-0.62, -0.10, 0.00, 0.31, 0.88], dtype=np.float32)   # 실수 weight 다섯 개

lo, hi = float(w.min()), float(w.max())
scale = (hi - lo) / 255                       # 정수 한 칸이 실수로 얼마인가
zero = int(round(-128 - lo / scale))          # 실수 0.0이 놓일 정수 자리
q = np.clip(np.round(w / scale) + zero, -128, 127).astype(np.int8)
back = (q.astype(np.float32) - zero) * scale  # 다시 실수로

print("scale", round(scale, 5), "zero_point", zero)
print("정수 ", q.tolist())
print("복원 ", [round(float(v), 3) for v in back])
print("오차 최대", round(float(np.abs(back - w).max()), 4))
scale 0.00588 zero_point -23
정수  [-128, -40, -23, 30, 127]
복원  [-0.618, -0.1, 0.0, 0.312, 0.882]
오차 최대 0.0024

4바이트짜리 숫자가 1바이트가 되었고, 되돌렸을 때 오차는 0.0024 이하입니다 [실측·PC]. 실수 0.0은 정확히 0으로 돌아옵니다. 그렇게 되도록 zero_point 를 정했기 때문입니다.

이 계산에서 범위(lo, hi)를 무엇으로 정하느냐가 대표 데이터셋의 일입니다. weight는 모델 안에 있으니 바로 보이지만, 계산 중에 흐르는 값(활성화 값, activation)은 실제 입력을 흘려 봐야 범위를 압니다. 대표 데이터셋이 실제보다 좁으면 큰 값이 127에 잘리고, 넓으면 칸이 거칠어집니다. 어느 쪽이든 오류는 나지 않습니다.

교재 2부 4-3프루닝(pruning)과 지식 증류(knowledge distillation) — 개념

프루닝은 덜 쓰는 연결을 잘라 냅니다. 한(Han) 등은 학습 → 중요하지 않은 연결 자르기 → 다시 학습의 세 단계로 AlexNet 9배, VGG-16 13배의 파라미터를 줄였다고 보고했습니다 [R-10]. 여기서 가르칠 것은 “규칙 없이 흩어진 0은 연산 라이브러리가 건너뛰지 못하면 계산을 못 줄인다”는 점입니다. 채널이나 블록 단위로 통째로 잘라 내는 방식(구조적 프루닝)이 실제 속도로 이어지기 쉬운 까닭입니다 [의견].
